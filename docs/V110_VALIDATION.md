## Проверенное поведение

При подготовке кнопка «Сохранённые составы» открывает три именованных слота. Сохраняется текущий черновик: размер поля, составы и позиции обеих команд, арена, управление красными. Загрузка слота или применение кода меняют только черновик; принятый состав обновляется после проверки и «Начать бой». Последний принятый состав записывается отдельно от слотов и восстанавливается в подготовке при следующем запуске. Промежуточное состояние боя — HP/MP, ход, очередь, статусы и RNG — в формат не входит.

Перенос использует обычный JSON в текстовом поле. Импорт не загружает ресурсы и не исполняет объекты; неизвестные поля, версии, профили, арены, недопустимые размеры и позиции отклоняются. Ошибка импорта сохраняет прежний черновик. Размер поля импортируемого состава должен совпадать с текущим полем сцены.

`user://battle_setups.json` использует стабильное имя каталога `soulane`, запись через временный файл и резервную копию. При повреждении основного файла проверяется резервная копия; если допустимых данных нет, запись блокируется, исходные файлы сохраняются. Ошибка записи не выдаётся за успешное сохранение. В Web запись отклоняется, если `OS.is_userfs_persistent()` сообщает об отсутствии постоянного хранилища.

## Нативный интерфейс

В реальной сцене проверены сохранение именованного слота, загрузка в черновик, удаление с повторным нажатием, отклонение неверного кода и применение корректного кода. Затем приложение полностью закрыто и запущено заново с тем же изолированным каталогом пользовательских данных: подготовка восстановила ручное управление красными, сохранённую позицию С1 `(0, 0)` (в UI «Гекс 1, 1») и два именованных слота. Это проверка настоящего нативного перезапуска; автоматическая интеграция отдельно проверяет восстановление новой инстанцией сцены.

В окне 1440×900 проверены переносы подсказки переноса и длинного сообщения после экспорта: текст помещается в карточку, поле кода и кнопки доступны.

## Ограничения

Составы хранятся локально на устройстве, а в Web — в хранилище текущего браузера. Синхронизации через аккаунт нет. Для переноса между устройствами/браузерами и резервной копии нужен отдельно сохранённый код. Очистка данных браузера может удалить библиотеку.

Сохранность после закрытия и повторного открытия браузера, перенос кода между браузерами и полная браузерная партия v1.10 не проверены. В managed Sites окружении отсутствует `cua_repl.js`; браузерная проверка недоступна. Проверки нативного приложения, headless-тесты и Web-экспорт не подтверждают браузерную сохранность. Именно Godot 4.3 не проверен.

Пять прежних сценариев (`test_duel_v11`, `test_gdd_v09`, `test_matter_v10`, `test_monsters_v14`, `test_v13`) сохраняют сообщения CanvasItem RID / ObjectDB и `23 resources still in use at exit`. Все проверки проходят; новые сценарии v1.10 завершаются без этих сообщений.
