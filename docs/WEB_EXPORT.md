# Web-экспорт v1.6

Эта ветка добавляет воспроизводимый Web-экспорт поверх `codex/v1.6-enemy-ai`, коммит `8b0b8bb`. Боевые правила и игровой код не меняются.

## Сборка

Нужен Godot и соответствующий его версии шаблон экспорта Web. Сборка проверена официальным Godot **4.6.3 stable** и `web_nothreads_release.zip` той же версии.

```sh
python3 tools/export_web.py
# Или в отдельную папку:
python3 tools/export_web.py --godot godot --output /absolute/path/to/web-build
```

Профиль `Web` в `export_presets.cfg` использует Compatibility/WebGL2 и **один поток**: SharedArrayBuffer и специальные COOP/COEP-заголовки для многопоточности не требуются. Документы и тестовые сценарии исключены из пакета. Фокус передаётся игровому canvas при запуске. PWA/service worker отключён, чтобы старая версия не оставалась в его кеше.

Папка `builds/` уже исключена из Git. В репозиторий не добавляются экспортные шаблоны, `.godot/`, временные файлы или собранные бинарные ресурсы.

## Размещение

Публикуется содержимое папки сборки целиком. Стартовый файл — `index.html`. Файлы JS/PCK/WASM должны быть доступны по тому же origin; WebAssembly следует отдавать с `Content-Type: application/wasm`. Для запуска нужен HTTPS или localhost. Простое открытие HTML через `file://` не заменяет размещение.

Официальный `index.wasm` в этой сборке имеет размер **37 700 666 байт**, что превышает лимит 25 MiB на отдельный статический файл некоторых хостингов. В таком случае нужен хостинг с поддержкой этого размера либо корректная отдача сжатого WASM с `Content-Encoding: gzip`; одного переименования сжатого файла недостаточно. Ещё один корректный вариант — хранить явный `index.wasm.gz`, распаковывать поток через браузерный `DecompressionStream('gzip')` и передавать Godot исходные байты WASM. Этот вариант использован в приватном Site ниже; файлы игрового ядра не изменяются.

## Проверка этой сборки

Реально выполнены headless-импорт и release-экспорт в Godot 4.6.3: код завершения 0, обязательные файлы созданы, заголовок WebAssembly проверен. Игровые файлы совпадают с исходной v1.6. Браузерная проверка в этой среде не выполнена: `SITES_MANAGED_LINUX_CONTAINER=1`, а `cua_repl.js` недоступен. В соответствии с workflow Sites обходной локальный HTTP-сервер или другой путь управления браузером не запускался. Результаты прежних 17/1179 тестов движка относятся к v1.6 и не выдаются за браузерную проверку.

После публикации следует проверить в браузере загрузку, читаемость кириллицы, выбор и движение синих, автоматический ход красных, 1/2/F/Space/A/R/T и отсутствие конфликтов фокуса клавиатуры.

## Постоянный цикл итерации

Пользователь попросил публиковать каждую завершённую итерацию в ту же Web-версию. Итерация объединяет несколько связанных изменений в законченный сценарий: один PR, итоговые проверки, одна публикация. Промежуточные правки проверяются точечно; общий отчёт остаётся коротким. Следующую функциональность и баланс не придумывать ради объёма пакета.

1. Выбрать актуальную игровую базу и проверить текущую Web-версию: публикация из старого main не должна откатить более новую сборку. До объединения PR #5 и #6 в main инструменты Web-экспорта находятся в `codex/v1.6-web-preview`.
2. Завершить пакет, выполнить проверки по изменениям, зафиксировать исходники в Git. `export_web.py` записывает `.suleyn-export.json` с SHA исходников/артефактов; упаковка требует совпадения с текущим коммитом.
3. Открыть исходный репозиторий существующего Site через Sites tools, проверить его `.openai/hosting.json` и доступ. При отсутствии локальной копии получить её из репозитория Site; исходники сайта и Godot — отдельные рабочие копии.
4. Экспортировать и подготовить статические файлы командами ниже. Упаковщик обновляет только сгенерированную игру, `source.json` и метку версии/коммита, сохраняя идентичность Site и оболочку. Он не публикует и не читает токены.
5. Проверить подготовленный Site, зафиксировать и отправить его точные исходники, упаковать `.openai/hosting.json` и `dist/`, опубликовать штатным Sites workflow. Приватную публикацию применять только после подтверждения owner-only доступа. Дождаться `succeeded` и вернуть прежнюю ссылку.

```sh
python3 tools/export_web.py --output /absolute/path/to/export
python3 tools/prepare_web_site.py --export-dir /absolute/path/to/export --site-dir /absolute/path/to/site-checkout
# Проверка потоковой загрузки — в исходном репозитории Site:
node /absolute/path/to/site-checkout/scripts/validate-static.mjs
```

На стартовой странице Site слот версии имеет `id="build-label"`; рядом с версией выводится короткий коммит. `.openai/hosting.json` упаковщик не создаёт и не изменяет. Для публикации использовать Sites skill; исходный репозиторий Site требует краткоживущего доступа из native tools, который нельзя записывать в команды, Git или документы.
