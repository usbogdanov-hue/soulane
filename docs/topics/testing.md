# Тестирование

Сначала прочитать [общий контекст](../CHAT_CONTEXT.md) и `AGENTS.md` проверяемой ветки. В отчёте всегда указывать ветку, коммит, версию Godot и команды, которые действительно выполнялись.

## Основные файлы

- `tests/`: сценарии Godot и `offline_audit_v14.py`.
- `docs/V15_VALIDATION.md`: подробный прошлый отчёт **на ветке v1.5**, в исходном `main` v1.4 его нет.
- `scripts/` и `data/`: реализация и ресурсы для воспроизведения.

## Известный результат v1.5

Коммит `9461496`, Godot 4.6.3: 302 новые проверки; всего прошли 14 из 15 тестовых сценариев. Статический аудит 334/334, 206 ссылок на файлы. Основная сцена запускалась без ошибок скриптов. В окне 1440×900 проверены выбор, движение, пропуск, T и R. Это прошлый результат, его нельзя выдавать за повторный запуск или проверку Godot 4.3.

## Известная старая ошибка Inspector

`test_unified_inspector.gd` имеет два падения, воспроизведённых на исходной v1.4:

- `trimming prioritizes STR then AGI`
- `HP/MP growth after level decrease`

Уменьшение уровня 10 → 5 при STR18/AGI9 даёт STR3/AGI9 вместо ожидаемого STR12/AGI0 из-за порядка вызова setter в `_trim_points_to_budget()` файла `scripts/commander_profile.gd`. Исправление не входило в PR #1. После будущего исправления обновить этот статус и проверить зависимые расчёты характеристик.

Некоторые старые тесты печатают сообщения о неосвобождённых Demo-узлах при завершении. Новые тесты v1.5 освобождают их. Результат оценивать по коду выхода и сообщениям ошибок; один код выхода 0 сам по себе не доказывает отсутствие ошибок GDScript.

## Команды для v1.5

```sh
python3 tests/offline_audit_v14.py
godot --headless --editor --path . --import
godot --headless --path . --script res://tests/test_v13.gd
godot --headless --path . --script res://tests/test_monsters_v14.gd
godot --headless --path . --script res://tests/test_turns_v15.gd
godot --headless --path . --script res://tests/test_teams_v15.gd
```

Не все эти файлы есть в v1.4. Выбирать проверки по задаче. Статический аудит не исполняет GDScript и не заменяет движок. Для GUI/ввода выполнить отдельную проверку сцены, когда изменение её затрагивает.
